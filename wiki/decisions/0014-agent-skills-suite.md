# ADR 0014: Coding agents reach the framework through a skills suite shipped in the package, written by the Scribe from briefs

## Context

The engine ships as a package ([ADR 0007](/decisions/0007-engine-as-package.md)) and its starter pack is a directory of YAML files ([ADR 0006](/decisions/0006-starter-pack-split.md)), but a developer working inside Claude Code, Codex, Cursor, OpenCode or Gemini CLI had no way for that agent to discover the syndicates or know how to run, author, serve and remember with them: the knowledge lived in `DOCUMENTATION.md` and `QUICKSTART.md`, which no coding agent loads on its own. Three shapes were considered: an MCP server exposing "list syndicates / run syndicate" tools; a plugin per platform; a suite of Agent Skills — the SKILL.md format Anthropic published as an open standard, which every listed agent now reads from a small set of directories (`.claude/skills`, `.agents/skills`, and per-platform folders).

## Decision

Skills, in `skills/` at the package root, one directory per skill, six skills: `melchizedek` (the entry point and the catalog), `melchizedek-author`, `melchizedek-serve`, `melchizedek-memory`, `melchizedek-models`, `melchizedek-scribe`. They ship in the package's `files` and in the public mirror (each file allowlisted), and a fourth bin, `melchizedek-skills`, copies them into the directories the agents read — `.claude/skills/` and `.agents/skills/` by default, which between them reach every listed platform, with per-platform targets and a global flag; the community `skills` CLI also installs them from the public repo. Skills over an MCP server because the agent needs procedures and judgment (which syndicate fits, what a run costs, what the output means, what not to obey), which a tool schema cannot carry, and because a skill runs the existing bins rather than adding a second runtime surface to secure. Skills over per-platform plugins because one standard directory layout reaches all of them.

The prose is generated. A new starter-pack syndicate, [the Scribe](/agents/scribe.md), writes each SKILL.md from a brief — audience, kind, purpose, facts, identifiers that must appear verbatim, limits — and audits the draft against the brief through a JSON-schema leaf before returning it. The briefs are kept in `skills/briefs/`, beside the prose, and a skill changes by changing its brief and rerunning; a person reviews every result. This makes the suite an instance of the framework rather than documentation about it, and it keeps the six skills in agreement through one shared facts block.

## Consequences

The package gains a versioned surface a coding agent depends on: a renamed bin, flag or path breaks a skill, so `skills/briefs/_shared.md` joins the list of mirrors a CLI change must update, and the export allowlist grows by one line per skill file. The installer is deliberately dumb — copy, never overwrite a differing file without `--force`, follow no symlinks — so an installed skill a user edited is never clobbered by a package upgrade; the cost is that upgrades need `--force` or a manual merge. The suite is a second thing on melch.ai and in the public README to keep current, and the starter pack is now seventeen files, which every count in the docs and the site copy had to follow. The private discipline skills in `.claude/skills/` remain a different thing and never export.
